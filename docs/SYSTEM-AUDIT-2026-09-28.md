# Website system audit — 28 September 2026

Audit base: main `212ef3169d1145d04bc786cbd07143a51ad0f465`. The audit used an isolated checkout, local PostgreSQL fixtures, mocked external delivery services and read-only production checks. No customer orders, payments, subscribers or email sends were created by this audit.

## Fixes and measured improvements

- Custom Orders and Pastries were using full-size photographs for small gallery tiles. Added 583 WebP thumbnails, also used in the gallery admin. Across the current gallery library, thumbnail bytes total 24,247,584 versus 505,560,736 original bytes: 95.2% smaller. This is an aggregate file-size comparison, not a claim that visitors download the entire library or that every connection is 95% faster. Originals load when enlarged; failed thumbnails retry the original before displaying an unavailable-photo message.
- Inspected the actual image formats behind 620 published gallery records / 583 unique photo URLs. Found 580 WebP originals and three JPEG/MPO originals. Converted the latter to full-resolution WebP: 7,941,986 bytes became 2,886,228 bytes. Original source files remain preserved. The website recognizes old saved JPEG URLs during deployment. Every thumbnail was decoded/verified as WebP, at most 640 pixels on its longest edge; none of the source images contained transparency.
- Added six indexes for order history, action keys, payment approvers, promo users and newsletter campaign relationships. These are already applied to production and verified. Supabase's missing-foreign-key-index findings cleared. Current data volumes are small; the purpose is to keep lookups and relationship checks efficient as records accumulate.
- Removed unnecessary browser execution permission from Supabase's internal `rls_auto_enable()` event-trigger function, retaining the trigger and its owner access. The migration was verified as repeatable and preserves the trigger. The browser-facing API functions retain their existing explicit authorization checks, consistent with [Supabase's function permission guidance](https://supabase.com/docs/guides/api/securing-your-api).
- Replaced 15 nonexistent `specialties.html` dropdown destinations with the existing Pastries destination, retaining dropdown behavior.
- Repaired stale browser test adapters, Windows path checks, a fake invalid PNG upload fixture and tests still expecting native confirmations. Unmocked client calls continue to fail; tests never fall through to production writes. The normal unit-test command now discovers every `tests/*.test.mjs` file, including accounting, Academy and newsletter coverage previously omitted by the hardcoded list.

## Reproduction

Use Node 24 and the existing pinned ExcelJS 4.4.0 test bundle via `EXCELJS_TEST_PATH`. Set `PGLITE_PACKAGE_ROOT` to the directory containing `@electric-sql/pglite`. Run `npm test` for all unit, database and backend-function checks. Browser tests use `PLAYWRIGHT_PACKAGE_ROOT` and optional `BROWSER_EXECUTABLE_PATH`; run the scripts in `tests/ui` and `tests/newsletter-ui.mjs`. Academy integration requires the loopback `scripts/academy-preview.mjs` server and `ACADEMY_TEST_BASE` / `ACADEMY_PREVIEW_URL`. Generate email fixtures with `node --experimental-transform-types scripts/preview-emails.mjs`. HEIC conversion tests accept `HEIC_TEST_DIR` / `HEIC_TEST_FILES` and keep converted personal images local.

To rebuild portfolio thumbnails, pass an explicit JSON array of existing public gallery URLs to `python scripts/gallery-thumbnails.py <urls.json>` using Pillow. The script reads local public originals, preserves them, and writes the thumbnail assets and map. New owner-uploaded gallery images continue through the existing WebP conversion pipeline; unmapped photos use their validated original until a thumbnail is generated.
