# Academy album loading

Switching a batch updates its gallery and video section synchronously, preserving the class header, hero and album selector. The selected batch's first 24 photos are prioritized, then its remaining photos are downloaded gradually with two low-priority image requests at a time. Metadata/signing work stays in groups of 24. Album covers and other page images still resolve near the viewport. Other batches' activity photos are never preloaded.

The cache lasts for this page instance only and renews links after four minutes, one minute before Storage's five-minute expiry. Concurrent requests share pending work. A detached gallery cannot be updated by a late response. Swiping prioritizes the next eight and previous two photos ahead of sequential warming. Changing class or batch disposes its previous preloader. Background tabs pause new work; Data saver and 2G connections warm the first page plus requested swipe neighbors. The lightbox requests its current photo immediately and reserves a stable height while loading.

Verification: `node tests/academy-loading.test.mjs`, `node tests/academy-preload.test.mjs`, `node tests/ui/academy-lazy-loading.mjs`, `node tests/ui/academy-public-albums.mjs` and `node tests/ui/academy-photo-refresh.mjs`. Browser checks use the existing Playwright runtime environment variables. The 2,600-photo fixture covers delayed responses, background image bytes beyond photo 24, swipe to photo 25, canceled old-batch work, expired URLs, history/refresh, retry and preservation of the class DOM.

Measured on 27 September 2026 using Chrome at 390×844 against the live catalog, with the changed assets intercepted locally: a new batch switched its heading in 32 ms and displayed its first photo in 1.25 seconds, versus 14.02 and 14.33 seconds before. Revisiting the previous batch took 50 ms with no image-link API calls. New-batch signing dropped from 2,117 to 24 photos. These are one-run development measurements, not a mobile-network SLA.

No image files, album records, consent settings or Storage permissions are changed by this frontend fix. The earlier `academy_bulk_asset_access` database migration, already applied during the import, is included in source control to preserve that prerequisite.
