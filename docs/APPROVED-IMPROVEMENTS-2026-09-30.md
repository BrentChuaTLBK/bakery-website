## Regression findings and corrections

- The initial combined run passed 53/54 suites. The delivery-zone browser check read the rendered description before the completed save had refreshed its card. It now waits for that observable rendered state, and still asserts exact content, escaping and formatting.
- The alert migration's focused fixture caught the outbox constraint rejecting a message without an order. The constraint now explicitly allows only the new operational type alongside the existing newsletter types.
- Operational contracts run in a fresh database, like the existing voucher contracts, because historical upgrade tests intentionally restore old functions/constraints. This prevents a historical fixture from being mistaken for the final schema.
- Review of the POS launch found that sign-in dropped `#pos`. The sign-in return now preserves the POS destination, with an OAuth-return regression.
- The monitor covers newsletter Broadcast jobs as well as transactional email jobs; it does not report healthy provider polling as a failure.
